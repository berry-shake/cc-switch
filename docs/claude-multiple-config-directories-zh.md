# Claude 多配置目录扫描

在「设置 → 高级 → 配置目录 → Claude 额外扫描目录」逐个添加配置根目录，例如 `~/.claude-work`。不要选择其 `projects` 子目录。支持手动输入和文件夹选择器，保存后生效，不要求重启。

## 扫描与配置写入分离

- `claudeConfigDir` 仍是唯一的主配置目录。未覆盖时使用 `~/.claude`；覆盖后不再额外隐式扫描默认目录。
- 新增 `claudeAdditionalConfigDirs: string[]`，保存在本机 `settings.json`，不改变供应商、MCP、Skills 的写入目标。
- 会话列表和用量导入使用相同的配置根列表，各自扫描根下的 `projects`。用量仍覆盖主会话、普通子代理和 Workflow 子代理。
- 保存后刷新会话缓存。开启自动同步时排队执行一次增量用量同步；手动模式只更新目录设置，仍需用户手动同步用量。
- 移除扫描目录不删除日志、同步游标或已入库历史统计。已不存在/不可读的目录会跳过，不阻塞其他根目录；稍后重新挂载可继续扫描。

## 来源、恢复和删除

- 会话保留 `sourceConfigDir` 和实际 `sourcePath`；不同目录中相同 session ID 的副本是独立列表项，显示来源目录名，悬停可看完整路径。
- 恢复/复制命令使用对应来源目录。自定义配置通过仅作用于该进程的 `CLAUDE_CONFIG_DIR` 传递；默认目录清除继承的同名环境变量，避免串到另一配置。路径和 session ID 均做 shell 引用。
- 文件读取和删除必须通过已配置扫描根的真实路径校验。删除只影响选中来源及其同名 sidecar；sidecar 为软链接时只移除链接。
- 真实路径去重可消除目录别名与软链接重复。递归会话扫描记录已访问目录，拒绝越界链接与循环。

## 用量与历史兼容

- 复用 `session_usage_dedup`，以 Claude `message.id` 对应的 `session:<id>` 持久去重；剪枝后的请求身份仍保留。不会修改现有计价公式，也不会重新计算历史费用。
- Schema 从 20 升至 21，新增 `claude_usage_legacy_cursors`，保存升级前游标快照。迁移从现存明细中补齐去重 ID；首次同步再从具有可验证边界指纹的已处理日志前缀中补齐 ID，不重新导入金额。
- 旧文件缺失、已被改写或只有无法验证的老游标时，会报告账本恢复未完成。旧版已经汇总且删除明细的时间段也受到保护，因为汇总本身不能恢复请求 ID。
- 在受保护时间范围内，没有去重证据的旧请求会暂停导入并保留读取断点；同文件中可确认的新请求仍正常导入。恢复原日志后可再次同步；不能通过清空游标/去重表来“解决”，否则可能重复计费。
- 因此，新加入目录中很久以前的真实新请求，也可能被保守暂停：它们与已汇总请求的副本无法仅凭现有数据安全区分。需要单独核对，不自动假定为新增消费。
- 导入明细、保存去重 ID、推进游标在同一事务内。导入失败则共同回滚。

## 验证与交付注意

回归覆盖添加/移除/取消选择、目录状态、缓存失效、自动/手动同步、软链接循环与越界、跨目录副本、子代理/Workflow、剪枝后去重、旧库迁移、原日志恢复以及事务失败重试。

本功能的开发测试只使用临时目录和测试数据库。实际安装交付时，应按现有流程成对备份应用与数据库；如回退到只支持 Schema 20 的旧程序，需要同时恢复对应备份，不能只替换应用。
