# v4.0.4 fork 合并说明

合并上游正式 tag `v4.0.4`，采用 v4 的侧栏、设置页和分块会话阅读器；不额外扩张页面功能。

## 保留的定制

- Claude 多配置目录扫描迁入「设置 → 应用配置 → Claude Code」。额外目录仍逐个添加，来源标识、按来源恢复/删除、安全路径校验、用量同步与持久去重保留。目录变化会清除旧来源的会话、分块正文缓存，不影响其他应用。
- OMP 在本应用中的供应商、MCP、Skills、提示词、会话和配置目录保持独立。新版提示词页面按应用区分请求、缓存与保存状态，不串用 Pi 的文件。此次不修改或更新外部 OMP 源码/安装。
- Codex 继续使用现有凭证存储模式、原始个人 Credits 口径、Fast 倍率和缓存语义；保留六格容量面板及独立预测，不恢复每日/模型 Credits 明细。
- 保留安全的手动 Codex 用量重建，不在升级中自动重算历史。Claude 用量导入结合上游完整输出/时延更新与本分支持久去重，数据库写入失败时回滚同步游标。
- 统计指标和请求表保持输入、缓存写入、缓存读取、输出的顺序；不把未报告的缓存写入展示成已知零值。汇总数量继续使用 K/M/B。

## 数据库与回滚

本分支原 schema v21 与上游 schema v20 的列集合不同，统一升级到 v22：按列存在性补齐 OMP、MiniMax Code 和 Pi 开关，不覆盖已有开关、同步游标和历史费用。两种布局及重复迁移均有回归测试。

安装前必须保存旧应用、SQLite 一致性快照和设备配置。回滚时同时恢复旧应用和升级前数据库，不能让旧版打开 schema v22。上游正常启动中的模型目录维护、日志保留及增量同步仍会执行；本次合并本身不触发历史重建。

macOS 本地构建使用 ad-hoc 签名，不宣称 Apple Developer ID 签名或公证。
